# 工作项 0.8：宿主运行时事件契约（SessionRunner）

| 项 | 值 |
| --- | --- |
| 状态 | ✅ 已完成（0.8.0） |
| 目标版本 | `statechart-kit@0.8.0` |
| 类型 | 功能增强（宿主 API） |
| 预估 | 0.5–1.5 人日（中位 1） |
| 实际 | 约 1 人日（含测试/回归） |
| 依赖 | 无；建议先于 Node-RED 宿主的运行时改造（P5/W4）完成 |
| 消费方 | `node-red-contrib-scxmljs`（`src/nodes/machine.ts`、`src/nodes/out.ts`） |

## 1. 背景

kit 的 P5 计划是让 `node-red-contrib-scxmljs` 改用本包作为核心，删除宿主的
`src/vendor/scxml-core` 与自维护的引擎加载器。当前阻碍不在 core，而在
`SessionRunner` 的事件契约：

- `RunnerEvent`（[session-runner.ts](../../src/engine/session-runner.ts#L49)）只有
  `active / fired / send / log / stopped`，是给编辑器仿真面板设计的；
- `send` 只带 `{ name, data }`，丢掉了引擎的 `target` / `sendid` / `type`；
- `done` / `error` 只写中文日志，没有强类型事件。

这对 Node-RED 宿主是实质性缺口：

1. **内部 send 过滤失效**：宿主输出节点用
   `target === '#_internal' || !!sendid` 过滤内部发送（`includeInternalSends` 默认
   `false`）。延时转移在序列化时展开为 `send <event> delay ... id <event>`
   （[serializer.ts](../../src/core/serializer.ts#L103-L107)），其 `sendid` 即自动事件名；
   拿不到 `sendid` 就无法过滤，内部事件会泄漏到输出 2。
2. **`done` 无法结构化处理**：宿主需要据此更新节点状态并发出 `done` 事件，目前只能
   从中文日志文本里猜。
3. **`error` 无法结构化处理**：宿主需要 `node.error()` 与 `error` 总线事件，并把
   引擎原文放进 `params.detail`；目前只有拼好的中文日志。

宿主侧的唯一绕法是用 `runner.sessionOrNull` 直接挂 `addEventListener`，但这会
绕过 P2 的 generation 生命周期加固、监听器隔离与新增事件分发，等于放弃
`SessionRunner` 的价值。因此应在 kit 侧补齐事件契约。

## 2. 目标

1. `RunnerEvent` 增加 typed 的 `send`（含 `target` / `sendid`）、`done`、`error`；
2. 现有事件、日志、生命周期行为零变化（编辑器仿真面板不受影响）；
3. 新类型可从 `statechart-kit/engine` 直接 `import type`；
4. 发布 `0.8.0`，供宿主锁定精确版本。

## 3. 非目标

- 不做运行日志结构化或多语言：日志仍是自由中文文本，宿主自行 localize 自己的
  code 表；本项只保证 typed 事件带 `kind` / `message`；
- 不在 kit 里提供 `isInternalSend()` 之类的宿主策略：`target` / `sendid` 是引擎
  事实，过滤规则由宿主决定；
- 不给 `active` 增加触发事件名（宿主的 `currentEvent` 语义不同，见 §8）；
- 不修改 `start / send / stop / snapshot / assignVariable / assignValue` 的签名；
- 不改编辑器 UI，不改 `SimLogEntry`，不加 MQTT / 路由 / 服务端能力。

## 4. API 变更

在 [session-runner.ts](../../src/engine/session-runner.ts) 中新增并导出以下类型
（`src/engine/index.ts` 已 `export *`，无需改导出面）：

```ts
import type { SCXMLErrorKind } from '@tinyactors/scxmljs/trusted'

export interface RunnerActiveEvent {
  type: 'active'
  ids: string[]
}

export interface RunnerFiredEvent {
  type: 'fired'
  pairs: FiredPair[]
}

/** 一次 <send> 被引擎派发（已过 delay；delay=0 时在微步内同步派发）。 */
export interface RunnerSendEvent {
  type: 'send'
  /** 事件名；非 SCXML 处理器可能为空串 */
  name: string
  /** <send> 载荷；未提供时 undefined */
  data?: unknown
  /**
   * 目标，原样透传：
   * ''            默认（外部 / 自身队列）
   * '#_internal'  内部队列
   * '#_parent' / '#_scxml_<sessionId>' / invoke id / 自定义 URI
   */
  target: string
  /** <send id> / idlocation；仅声明时存在（匿名延时发送没有） */
  sendid?: string
}

export interface RunnerDoneEvent {
  type: 'done'
  /** 顶层 final 的 <donedata>；cancel 后恒为 undefined */
  data: unknown
}

export interface RunnerErrorEvent {
  type: 'error'
  /** error.execution | error.communication | error.platform */
  kind: SCXMLErrorKind
  /** 人读信息，格式不承诺稳定 */
  message: string
}

export interface RunnerLogEvent {
  type: 'log'
  entry: SimLogEntry
}

export interface RunnerStoppedEvent {
  type: 'stopped'
}

export type RunnerEvent =
  | RunnerActiveEvent
  | RunnerFiredEvent
  | RunnerSendEvent
  | RunnerDoneEvent
  | RunnerErrorEvent
  | RunnerLogEvent
  | RunnerStoppedEvent
```

`on(l: (ev: RunnerEvent) => void)` 的签名保持不变。

## 5. 行为规范

| 事件 | 触发时机 | 字段来源 | 备注 |
| --- | --- | --- | --- |
| `send` | 引擎派发 `<send>`（`SendEvent`），在同一微步内、该宏步的 `active` 之前 | `e.message.event / target / data / sendid` | 每个 `<send>` 恰好一次；现有 send 日志保留 |
| `done` | 会话到达顶层终态（`DoneEvent`） | `e.data` | 会话仍是 `running`，直到显式 `stop()` |
| `error` | 会话抛出 SCXML 错误（`SCXMLErrorEvent`） | `e.kind / e.message` | 这是 SCXML 错误事件，不是崩溃；图表仍可 transition on `error.*` |

顺序约定：

```text
start → (active) → [send | log | error]… → active → … → done → stopped
```

- `send` / `log` / `error` 在微步内派发，`active` 在宏步末尾派发；本项只做透传，
  不改变引擎的派发顺序；
- 先写日志，再派发对应的 typed 事件（保持现有日志顺序）；
- `start()` 失败仍以 **抛异常** 表达，不额外发 typed `error`，避免宿主双报；
- `stop()` 时若已有会话，仍先派发 `stopped`（行为不变）。

边界语义：

- `target` 恒为字符串，默认值是 `''` 而不是 `undefined`；宿主不要用 falsy 判断，
  保持 `target === '#_internal'`；
- `sendid` 只在 `<send id>` / `idlocation` 存在时出现；匿名延时发送没有 `sendid`，
  这是引擎现状，不在本项修正；
- `done.data` 与引擎 `DoneEvent.data` 同形；cancel 后为 `undefined`；
- `sendType` / `error.element` 暂不进入公共契约；需要时再作为可选字段扩展。

## 6. 实现指引

改动集中在 [session-runner.ts](../../src/engine/session-runner.ts) 的三处监听器
（当前 `onError` 246 行、`onDone` 250 行、`onSendEv` 254 行）：

```ts
const onError = (e: SCXMLErrorEvent): void => {
  if (!current()) return
  this.log('error', `${e.kind}: ${e.message}`)
  this.emit({ type: 'error', kind: e.kind, message: e.message })
}

const onDone = (e: DoneEvent): void => {
  if (!current()) return
  this.log('lifecycle', '会话已到达终态结束')
  this.emit({ type: 'done', data: e.data })
}

const onSendEv = (e: SendEvent): void => {
  if (!current()) return
  const name = e.message.event
  const data = e.message.data
  this.log('send', `发送事件 ${name}${data !== undefined ? ` ${JSON.stringify(data)}` : ''}`, { data })
  this.emit({
    type: 'send',
    name,
    data,
    target: e.message.target,
    ...(e.message.sendid !== undefined ? { sendid: e.message.sendid } : {}),
  })
}
```

同时更新文件头注释中的事件列表，并在 `FiredPair` 附近补充新的接口定义。

## 8. 宿主消费契约（Node-RED）

| 宿主事件 | 来源 | 映射 |
| --- | --- | --- |
| `state` | `active` + `runner.snapshot()` | 宿主计算 `changed` / `event` / `ts` |
| `send` | `send` | `event: ev.name`、`data: ev.data`、`target: ev.target`、`sendid: ev.sendid`；过滤条件保持 `target === '#_internal' || !!sendid` |
| `error` | `error` | `new Error(kind + ': ' + message)`；不传 `element` |
| `done` | `done` | 更新节点状态，不自动 `stop()` |
| 日志 | `log` | 宿主可忽略或转 `node.debug` |

宿主侧目标写法（本项完成后应能删除 `sessionOrNull` 直挂）：

```ts
runner.on((ev) => {
  switch (ev.type) {
    case 'active':
      publishState(ev.ids, runner.snapshot())
      break
    case 'send':
      if (ev.target === '#_internal' || ev.sendid) return
      bus.emit({ type: 'send', event: ev.name, data: ev.data, ts: Date.now() })
      break
    case 'error':
      node.error(new Error(`${ev.kind}: ${ev.message}`))
      bus.emit({ type: 'error', error: new Error(ev.message), ts: Date.now() })
      break
    case 'done':
      node.status({ fill: 'grey', shape: 'dot', text: 'done' })
      bus.emit({ type: 'done', ts: Date.now() })
      break
  }
})
```
