> 状态：已实现（0.16.0）；测试环境已验证
>
> 类型：Vue 公开 API + 画布交互；不改 `ProjectDoc` / SCXML / 引擎语义
>
> 目标版本：`0.16.0`（默认关闭；后续 minor 再评估默认开启）
>
> 实际：约 6 人日（实现 + 测试 + 宿主接入 + 部署）
>
> 预估：**6–7 人日**（kit P50 约 5.5、宿主约 1；区间 5.75–7.5；上游契约 0.5–1 与可选浏览器 E2E 另计）

>
> 相关：[`kit-requirements.md`](../kit-requirements.md) KIT-017、[`roadmap.md`](../roadmap.md) P4.9

## 1. 问题与现状

官方 `<scxml-view>` 把转移标签里的条件渲染为 `[part="cond"]`，但文本只保留
`truncate(cond, 22)`（约 22 字符，尾部 `…`）。完整条件写在标签的 `title` 里
（`事件 [完整 cond] → 目标`）。由此带来：

- 编辑器画布可以用浏览器原生 `title` 悬浮查看，但样式不可控、延迟长；
- 详情/画廊使用 `passive` 画布（`pointer-events: none`）时标签收不到 hover，
  原生 tooltip 根本不出现；
- 移动端没有 hover；
- 宿主直接读取/改写官方 shadow DOM 的 `title`，复制渲染器契约。

宿主 `scxml-creator` 已在 `MachineCanvas` 中临时实现（约 150 行）：passive 画布只给
`::part(edge-label)` 恢复 `pointer-events`，用 `composedPath()` 找标签并读取 `title`，
`Teleport` 到 body 显示自定义 tooltip，期间移除原生 `title`。该实现已通过生产 trial
和 `scripts/check-machine-tooltip.cjs`，但只覆盖详情页，且存在以下局限：

- `part="edge-label"`、`part="cond"`、`title` 格式在宿主和 kit 各维护一份；
- 通过 `title` 反向解析，没有直接使用文档里的 `transition.cond`；
- 只覆盖详情页，不覆盖编辑器和 gallery；
- 跨 shadow root 的 `aria-describedby` 在规范上不成立，AT 很可能不播报；
- 仿真时渲染器会改写 `title`，删除/恢复 `title` 存在竞态。

kit 已有可复用资产：

- [`canvas-select.ts`](../../../src/vue/canvas-select.ts) 的 `matchTransitionId()` 已处理
  条件截断前缀、internal-only 生成守卫、无 target 的 chip、eventless；
- [`ChartCanvas.vue`](../../../src/vue/ChartCanvas.vue) 已集中维护 `OFFICIAL` 渲染契约；
- 宿主已经 import `statechart-kit/vue/style.css`，样式可随包提供。

因此本需求不是“再加一个 tooltip”，而是把**渲染契约、标签解析、交互和可访问性**
收敛到 kit 的一处实现，编辑器与所有宿主画布共用。

## 2. 目标

1. 导出可复用的 `<ScxmlLabelTooltip>`，适用于任意包装 `<scxml-view>` 的宿主组件，
   不只 kit 的 `ChartCanvas`；
2. `ChartCanvas` 增加 opt-in feature，默认关闭，不改变现有行为；
3. 标签与文档转移的映射优先使用**结构化属性**，`title` / `part` 只作为旧渲染器回退；
4. 直接显示 `ProjectDoc.transitions[].cond` 全文，不解析 `title` 文本；
5. 支持 hover / focus / 触摸 tap / Escape / 滚动 / 重绘 / 仿真态；
6. 可访问性正确：可聚焦、焦点环、同树 `aria-describedby`、屏幕阅读器可读；
7. passive 画布只恢复标签的 `pointer-events`，页面滚动和其余区域穿透不受影响；
8. 不改变 SCXML 语义、引擎、文档模型；不引入新运行时依赖。

## 3. 非目标

- 不做上游渲染器自己的原生 tooltip（长期可另议）；
- 不把 tooltip 做成富文本/HTML 渲染，只显示纯文本；
- 不做完整 ARIA live region / 状态播报；
- 不新增 `statechart-kit/core` 或 `engine` 入口；
- 暂不新增非 Vue 的 `statechart-kit/tooltip` 入口（controller 不依赖 Vue，后续可加）；
- 不改变事件可见性、延时、MQTT、变量等宿主语义。

## 4. 方案选择

| 方案 | 内容 | 判断 |
| --- | --- | --- |
| A. 只在 `ChartCanvas` 加逻辑 | 改动最小，但详情页仍用宿主临时实现 | **否**：没有解决“通用能力”和重复契约 |
| B. 把宿主 150 行搬进 kit | 快，1.5–2 人日可完成 | **否**：继续解析 `title`，跨 shadow aria 仍有问题，仿真态竞态未解 |
| C. 只等上游渲染器加原生 tooltip | 所有宿主受益 | **否**：不可控，且被动画布/移动端/a11y 仍需宿主决定 |
| D. 上游结构化属性 + kit 统一 resolver + 独立 controller + Vue wrapper | 一次性把契约、交互、a11y、测试补齐 | **推荐** |

方案 D 的核心是：**先把“标签是什么转移”变成精确信息，再做 UI**。工具提示只是
resolver 的第一个消费者；画布点击选中、后续 Explorer/键盘导航都可以复用同一份
标签事实。

## 5. 推荐架构

### 5.1 分层

```text
@tinyactors/scxmljs
  label: data-transition-id / data-cond / data-event / data-target
         + 现有 part="transition edge-label" / part="cond" / title（回退）
        │
        ▼
kit canvas-contract + transition-resolver
  标签 → LabelFacts → TransitionEdge
        │
        ├── ChartCanvas 点击选中（复用同一 resolver）
        │
        ▼
kit LabelTooltipController（纯 DOM，无 Vue）
  hover / focus / touch / title 归属 / 可聚焦性 / 同树描述
        │
        ├── <ScxmlLabelTooltip>（Vue 薄包装）
        │       ├── ChartCanvas
        │       └── MachineCanvas（详情 / gallery）
        │
        └── 未来：statechart-kit/tooltip 入口（非 Vue 宿主）
```

### 5.2 上游契约（首选，非阻塞）

在 `@tinyactors/scxmljs` 的 `#label()` 中给标签增加结构化属性：

```ts
el.setAttribute('data-transition-id', tr.element?.getAttribute('data-kit-transition-id')
  ?? tr.element?.getAttribute('id') ?? '')
if (tr.cond) el.setAttribute('data-cond', tr.cond)
el.setAttribute('data-event', tr.events.join(' '))
el.setAttribute('data-target', tr.targets.map((s) => s.id).join(','))
```

- `data-kit-transition-id` 是 kit 序列化器自 0.11.0 起写入的转移标识（KIT-007），
  上游只做**透传**，不需要知道 kit 的语义；
- `data-cond` 是完整条件，不截断；
- `data-event` / `data-target` 让点击选中和 tooltip 都不再依赖 `title` 文本格式；
- 保留 `title` 作为旧宿主/原生 tooltip 的回退；
- 标签被重绘时属性随之重建。

上游改动很小，但需要单独发版。**不把它作为 kit 发布的前置条件**：kit 同时实现
feature detection + 回退路径，旧渲染器仍可用。

回退契约（与现状一致）：

- 标签：`part` 含 `edge-label`；
- 事件：`part="event"` 文本；
- 条件：`part="cond"` 文本（可能截断，尾部 `…`）；
- 目标：`title` 中最后一个 `→` 之后的目标 id 列表；无 target 的 chip 为空。

### 5.3 kit 统一 resolver

新增 `src/vue/canvas-contract.ts`（模块内部使用；只把 `LabelFacts` 作为 formatter
参数类型从 vue 入口导出）：

```ts
export interface LabelFacts {
  label: HTMLElement
  /** 结构化转移 id；旧渲染器为 null */
  transitionId: string | null
  /** 完整条件；旧渲染器只能拿到截断文本 */
  cond: string | null
  /** `part="cond"` 的可见文本（含方括号，可能截断） */
  condText: string
  events: string[]
  targets: string[]
  eventless: string
}

export function labelFacts(label: HTMLElement, eventless: string): LabelFacts
export function labelFromEvent(e: Event): { label: HTMLElement; facts: LabelFacts } | null
export function resolveTransition(doc: ProjectDoc, facts: LabelFacts): TransitionEdge | null
```

优先级：

1. `facts.transitionId` 命中 `doc.transitions[].id` → 精确返回，不再匹配；
2. 有 `facts.cond`（结构化完整条件）→ 事件/目标/完整 cond 精确匹配；
3. 否则走现有 `matchTransitionId()`（截断前缀 + internal-only 守卫 + eventless）。

配套改动：

- 把 `ChartCanvas` 的 `OFFICIAL`、`edgeLabelFromPath()`、`transitionIdFromLabel()`
  移到 `canvas-contract.ts`；
- `ChartCanvas` 的点击选中改用 `labelFromEvent()` + `resolveTransition()`；
- `matchTransitionId()` 增加可选的完整条件字段，消除“同事件/同目标/同前缀”歧义；
- `OFFICIAL` 不公开导出，避免把渲染器契约变成 kit 公共 API。

### 5.4 LabelTooltipController（纯 DOM）

新增 `src/vue/label-tooltip.ts`，不依赖 Vue：

```ts
export interface LabelTooltipOptions {
  getDoc: () => ProjectDoc | null
  enabled?: () => boolean
  passive?: boolean
  formatter?: (t: TransitionEdge, facts: LabelFacts, doc: ProjectDoc) => string
  showDelay?: number   // 默认 120ms
  hideDelay?: number   // 默认 80ms
}

export interface LabelTooltipController {
  update(): void
  hide(): void
  destroy(): void
}

export function createLabelTooltip(
  view: HTMLElement,
  options: LabelTooltipOptions,
): LabelTooltipController
```

职责：

- 在 view 上做**事件委托**，不给每个标签挂 listener；
- 懒创建 body 下的 `.sce-label-tooltip`，复用单个 DOM；
- 管理 show/hide 定时器、当前标签、保存的 `title` / `aria-describedby` / tabindex；
- 管理可聚焦性注入和重绘后的重加；
- 在显示期间“拥有”标签的 `title`：外部（仿真重绘）重新写入时再次移除；
- 监听 view 的 `scxml-load`、文档身份变化、方向/resize 重绘，隐藏 tooltip 并重扫标签；
- `enabled` 变为 false 时立即隐藏并恢复属性；`formatter` 抛错时回退默认 `[cond]` 并
  `console.warn`，不让宿主 formatter 打断画布交互；
- 卸载时恢复所有被改写的属性，移除 observer、全局 listener 和 tooltip 节点。

### 5.5 仿真态的 title 归属

上游 `#renderState()` 会在每次状态变化时改写按钮 `title`（追加 inactive 提示）。
如果只是“显示时删、隐藏时恢复”，仿真重绘会打架。处理方式：

- 显示时保存一次原始 `title`，删除属性；
- 对该标签启动 `MutationObserver({ attributes: true, attributeFilter: ['title'] })`；
- 回调发现外部重新写入 `title` 时，断开 observer → 再删除 → 重新 observe；
- 不把外部写入的降级值覆盖到已保存的原始值；
- 隐藏/卸载时若标签仍连接，恢复原始 `title`；标签已重建则丢弃。

这样仿真态也能安全显示；tooltip 显示期间原生 tooltip 不会弹出。

注意：仿真时上游会把不可触发的标签置为 `disabled`。部分浏览器不给 disabled 表单
控件派发 pointer 事件，这类标签不显示 tooltip 是预期行为；active 标签仍正常显示。
如果后续要求 disabled 标签也可查看条件，需要上游改成 `aria-disabled`，不在本项范围。

### 5.6 可聚焦性与键盘

- 扫描 `[part~="edge-label"]`，只对带条件的标签注入 `tabindex="0"`；
- 已有 `tabindex` 的标签不覆盖；`<button>` 已可聚焦时可不加；
- 用 `data-sce-tip-focus` 标记“由 tooltip 注入”，禁用/卸载时只移除自己加的；
- `scxml-load`、方向切换、resize 导致 `#renderAll` 重建标签后，用
  `MutationObserver({ childList: true, subtree: true })` + `requestAnimationFrame`
  重加；只观察 childList，不观察 attributes，避免和 title/aria 写入形成环；
- `focusin` 立即显示，`focusout` 延迟隐藏，`Escape` 立即隐藏；
- CSS 增加 `::part(edge-label):focus-visible` 焦点环，仅作用于启用 tooltip 的 view。

### 5.7 可访问性：同树描述

宿主的跨 shadow `aria-describedby` 不可靠：IDREF 在元素所在 tree 内解析，shadow
root 与 document 是两个 tree。推荐做法：

- 显示时在**标签所在的同一 tree** 创建一个视觉隐藏的 `<span id="sce-desc-…">`：
  - 标签在 shadow root 内 → 追加到该 shadow root；
  - 标签在 light DOM → 追加到 document body；
- `aria-describedby` 指向这个 span，保存并恢复标签原有的 `aria-describedby`；
- 可见的 `.sce-label-tooltip` 放在 body，设 `aria-hidden="true"`，只负责视觉，
  避免屏幕阅读器重复朗读；
- shadow root 内的隐藏 span 用构造样式表（`adoptedStyleSheets`）注入
  `.sce-sr-only`；**追加，不覆盖**渲染器已有的 adoptedStyleSheets；light DOM fallback
  用 `styles.css` 中的同名类；
- `CSSStyleSheet` 不可用时退化为内联样式，并在文档中注明 CSP 影响；
- 若 shadow root 为 closed、无法插入描述节点，退化为 `aria-description`（不支持时
  临时在 `aria-label` 末尾追加条件，隐藏时恢复）；
- 可见 tooltip 文本使用 `textContent`，不使用 `innerHTML`。

### 5.8 passive / 触摸 / 手势

- 启用时给 view 加 `sce-label-tip`；passive 再加 `sce-label-tip-passive`；
- 只有 passive 类恢复标签指针事件：

```css
.sce-label-tip.sce-label-tip-passive::part(edge-label) {
  pointer-events: auto;
  cursor: help;
}
```

- 不全局改 `scxml-view::part(edge-label)`，避免普通编辑器画布被影响；
- 触摸：`pointerdown` 只记录起点，`pointerup` 位移 < 8px 且时间 < 500ms 才 tap 显示；
  位移超过阈值视为页面滚动/画布平移，取消；不在 `pointerdown` 上 `preventDefault`，
  保证 passive 页面滚动和编辑器平移不被破坏；
- hover 离开延迟 80ms；进入标签子 span 时用 `relatedTarget` 判断，避免闪烁；
- 滚轮/滚动/方向切换/文档变化/标签重建/窗口 resize 时立即隐藏；controller 自身用
  `ResizeObserver` 观察 view，布局变化时隐藏，避免 tooltip 停在旧位置；
- tooltip 本身 `pointer-events: none`，不会截获画布或页面手势。

### 5.9 Vue 组件与接入

`ScxmlLabelTooltip.vue` 是薄包装，只负责生命周期和 prop 同步：

```vue
<script setup lang="ts">
import { onBeforeUnmount, watch } from 'vue'
import { createLabelTooltip, type LabelTooltipController } from './label-tooltip'

const props = defineProps<{
  view: HTMLElement | null
  doc: ProjectDoc | null
  enabled?: boolean
  passive?: boolean
  formatter?: LabelTooltipFormatter
}>()

let control: LabelTooltipController | null = null

function sync(): void {
  control?.destroy()
  control = null
  if (!props.view) return
  control = createLabelTooltip(props.view, {
    getDoc: () => props.doc,
    enabled: () => props.enabled === true,
    passive: props.passive === true,
    formatter: props.formatter,
  })
}

watch([() => props.view, () => props.enabled, () => props.passive], sync, { immediate: true })
watch(() => props.doc, () => control?.update())
onBeforeUnmount(() => control?.destroy())
</script>

<template>
  <span class="sce-label-tooltip-anchor" hidden aria-hidden="true"></span>
</template>
```

`ChartCanvas`：

```vue
<ScxmlLabelTooltip
  :view="viewEl"
  :doc="editor.doc"
  :enabled="editor.features.canvasTransitionTooltip === true"
/>
```

`EditorFeatures` 增加 **optional** 字段：

```ts
export interface EditorFeatures {
  // ...
  /** 转移标签完整条件 tooltip（默认关闭） */
  canvasTransitionTooltip?: boolean
}
```

必须是 optional，否则现有宿主手写完整 `EditorFeatures` 对象会 typecheck 失败。
`DEFAULT_FEATURES` 同步增加 `canvasTransitionTooltip: false`。

宿主 `MachineCanvas`：

```vue
<ScxmlLabelTooltip
  :view="el"
  :doc="doc"
  passive
  :enabled="tooltip"
  :formatter="hostFormatter"
/>
```

- `doc` 必须传**部署版** `docSnapshot`，不是草稿；
- `hostFormatter` 可保持现有文案 `事件 [cond] → 目标`；
- 删除 `MachineCanvas` 中约 150 行 tooltip 状态、listener、CSS；
- 详情页 `:doc="detail?.deployed?.docSnapshot"`；gallery `:doc="c.doc"` 并打开 tooltip；
- 宿主 `scripts/check-machine-tooltip.cjs` 的 `.mc-tooltip` 选择器改为 kit 的稳定类名。

### 5.10 定位与样式

- `position: fixed`，controller 直接挂 body，避免被画布裁剪；
- 优先显示在标签上方，空间不足翻到下方；
- 水平按视口夹边，最大 `min(560px, calc(100vw - 16px))`；
- `white-space: pre-wrap; overflow-wrap: anywhere`，保留条件里的换行；
- 使用 `--scxml-*` 令牌，随 kit 明暗主题；
- `prefers-reduced-motion` 下关闭过渡；
- 文本使用等宽字体，和条件表达式一致；
- 不截断内容；极端长条件允许 tooltip 很高，必要时后续再加 `max-height` 与滚动。

## 6. 公开 API

```ts
// statechart-kit/vue
export { ScxmlLabelTooltip } from './ScxmlLabelTooltip.vue'
export type {
  LabelFacts,
  LabelTooltipFormatter,
  LabelTooltipProps,
} from './label-tooltip'

export interface LabelTooltipProps {
  view: HTMLElement | null
  doc: ProjectDoc | null
  enabled?: boolean
  passive?: boolean
  formatter?: LabelTooltipFormatter
}

export type LabelTooltipFormatter = (
  transition: TransitionEdge,
  facts: LabelFacts,
  doc: ProjectDoc,
) => string
```

默认文案为 `[cond]`；宿主需要完整标签文案时传 `formatter`。这样：

- kit 不引入新的中英文 labels；
- 宿主能保持现有 UX；
- tooltip 内容始终来自文档，不从 `title` 反解析。

`LabelFacts` 只作为 formatter 参数类型导出。`LabelTooltipController` /
`createLabelTooltip()` 暂不作为公共 API；controller 本身不依赖 Vue，未来若要支持
Node-RED 等非 Vue 宿主，可新增 `statechart-kit/tooltip` 入口而不重写逻辑。

## 7. 交互状态机

| 状态 | 进入 | 事件 | 动作 |
| --- | --- | --- | --- |
| `idle` | 初始 / 隐藏完成 | `pointerover` 标签 | 启动 show 定时器 → `pending` |
| `idle` | | `focusin` 标签 | 立即 `visible` |
| `idle` | | 触摸 `pointerdown` | 记录起点，保持 `idle` |
| `pending` | show 定时器未到 | `pointerout` / `focusout` | 取消定时器 → `idle` |
| `pending` | | 定时器到 | `visible` |
| `visible` | 已渲染 tooltip | `pointerout` 标签 | 启动 hide 定时器 → `hiding` |
| `visible` | | `focusout` / `Escape` / 滚动 / 滚轮 / 外部 `pointerdown` | 立即 `idle` |
| `visible` | | 触摸 `pointerup` 未移动 | 固定显示（pin） |
| `visible` | | 标签重绘 / 文档变化 / `scxml-load` | 立即隐藏、重建可聚焦性 |
| `visible` | | 外部改写 `title` | 重新移除，保持显示 |
| `hiding` | hide 定时器未到 | 重新 `pointerover` 同一标签 | 取消定时器 → `visible` |
| `hiding` | | 定时器到 | `idle`，恢复属性 |

所有定时器在 `destroy()` 中清理；所有属性恢复在 `hide()` / `destroy()` 中幂等执行。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 上游 `part` / `title` 契约变化 | 点击选中和 tooltip 同时失效 | 契约集中在 `canvas-contract.ts`；现有 contract probe；`check:vue` / 浏览器回归 |
| 上游结构化属性短期不发布 | 精确匹配不可用 | 保留完整回退路径；feature detection；不阻塞 kit 发布 |
| 仿真重绘改写 `title` | 原生 tooltip 复现、恢复错文案 | title 归属 + MutationObserver；只在显示期间接管；测试外部重写 |
| 同事件/同目标/同前缀歧义 | 显示错误 cond | 优先 `data-transition-id`；其次完整 `data-cond`；最后前缀匹配；歧义用例 |
| 跨 shadow `aria-describedby` | AT 不播报 | 同树隐藏描述节点；closed root 退化为 `aria-description` / `aria-label` |
| 触摸手势冲突 | 页面滚不动 / 画布拖拽失效 | 只在 `pointerup` 小位移时 tap；不 `preventDefault`；位移取消 |
| 标签重绘 / 方向切换 | tooltip 悬挂、tabindex 丢失 | `scxml-load` + childList observer + rAF 重加；活动标签断开即隐藏 |
| happy-dom 无真实标签 | 回归覆盖不足 | 假 shadow 测试 + 浏览器脚本 + 宿主 Playwright |
| 多实例 / 大图 | id 冲突、hover 性能 | 每实例唯一 id；事件委托；facts WeakMap 缓存；O(labels) 扫描 |
| 严格 CSP | 隐藏描述内联样式被拒 | 优先 `adoptedStyleSheets`，`styles.css` 提供类；退化内联样式需文档说明 |
