# KIT-016 — ProjectDoc `initial` 维护问题

> 来源：Node-RED 宿主 `@changzhen976/node-red-contrib-statechart@0.8.0-dev.1` 的 bug report：
> `node-red-contrib-scxmljs/docs/kit-bug-report-initial-state.md`
>
> 复现版本：`statechart-kit@0.11.0`；已在 `statechart-kit@0.12.0` 重新确认。
>
> 状态：已修复（0.12.1）

## 结论

`EditorStore` 的结构编辑操作修改 `ProjectDoc` 后，没有维护
`doc.initial` / `state.initial` 不变量：

- `addState`
- `removeState`
- `setParent`

`serializeToScxml()` 有“initial 为空则取第一个子状态”的 fallback，所以画布会画出
起始标记，但 `ProjectDoc` 仍然是空值；属性面板读文档，显示为空，校验器报
`structure.state.initial-fallback`。

这不是 `@tinyactors/scxmljs` 的渲染问题，也不是 Node-RED 宿主没有处理：完整编辑器
的新增/删除/移动状态由 kit 的 `EditorStore` 执行。

## 最小复现

在 Node 中直接使用 kit API，不需要 Node-RED 或浏览器：

```ts
import { createEditor } from 'statechart-kit/vue'
import { emptyDoc, serializeToScxml } from 'statechart-kit'

const editor = createEditor({ autoLoad: false, initialDoc: emptyDoc('root-case') })
await editor.ready
editor.addState('compound')
// doc.initial === null
// serializeToScxml 仍会写出 initial="state"
```

已确认：

```text
场景 A（第一个顶层状态）:
  docInitial: null
  xmlInitials: ['initial="state"']
  issues: ['structure.state.compound-empty']

场景 B（空白 compound 的第一个子状态）:
  parentInitial: null
  xmlInitials: ['initial="state"', 'initial="state2"']
  issues: ['structure.state.initial-fallback']
```

## 分项 Bug

### KIT-BUG-001：第一个顶层状态不设置根 `doc.initial`

- 组件：`EditorStore.addState`
- 期望：`doc.initial === 新状态.uid`
- 实际：`doc.initial === null`，依赖序列化 fallback
- 影响：ProjectDoc、属性面板、导出 SCXML 三处不一致

### KIT-BUG-002：空白组合的第一个子状态不设置 `parent.initial`

- 组件：`EditorStore.addState`
- 期望：`parent.initial === 子状态.uid`
- 实际：`parent.initial === null`，校验 warning
- 注意：`parallel` 不要设置 initial

### KIT-BUG-003：删除当前 initial 子状态后只置 null

- 组件：`EditorStore.removeState`
- 期望：`parent.initial` 自动指向剩余第一个合法子状态
- 实际：`parent.initial = null`，依赖 fallback
- 根节点已有类似 fallback，组合状态没有，行为不一致

### KIT-BUG-004：`setParent` 移入新组合不设置新父级 initial

- 组件：`EditorStore.setParent`
- 期望：新父级 initial 指向移入状态；旧父级 initial 指向剩余第一个子状态
- 实际：新父级 initial 仍为 null
- 影响：移动后属性面板为空、校验 warning

## 建议的统一修复

增加一个不变量 helper：

```ts
function ensureInitial(doc, parentUid) {
  // 根：doc.initial 必须指向一个顶层状态
  // compound：initial 必须指向一个直接子状态
  // parallel：不设置 initial
  // 无子状态：initial = null，保留 compound-empty 提示
}
```

调用点：

- `addState` 末尾：`ensureInitial(doc, parentUid)`
- `setParent` 末尾：旧父级 + 新父级 + 根
- `removeState` 末尾：受影响父级 + 根

不要删除 serializer 的 fallback：它对导入、手写 SCXML 和旧文档仍然有价值。本 bug 是
交互操作没有把 fallback 结果物化到 ProjectDoc，不是 fallback 本身错误。

## 回归测试

1. 空文档添加第一个顶层状态 → `doc.initial` 为该状态；
2. 空 compound 添加第一个子状态 → `parent.initial` 为该子状态；
3. 添加第二个子状态 → initial 不被覆盖；
4. 手动设置 initial 后删除它 → 自动指向剩余第一个；
5. 删除最后一个子状态 → initial 为 null，仅保留 compound-empty；
6. 唯一子状态移入空 compound → 新父级指向它，旧父级为空；
7. initial 子状态移出 → 旧父级指向剩余第一个；
8. history 作为第一个子状态时与 serializer 的选择一致；
9. 属性面板、ProjectDoc、serialize 三处一致；
10. 浏览器 smoke：空白 compound 加第一个子状态后属性面板立即显示，校验无
    `initial-fallback`。

## 验收

- 新建/删除/移动后，`ProjectDoc` 的 initial 与序列化 SCXML、属性面板一致；
- 不再出现 `structure.state.initial-fallback`，除非用户显式清空且仍有子状态；
- 旧文档导入和 fallback 兼容保持不变；
- 不要求 `ProjectDoc` 结构迁移。


## 0.12.1 实现记录

- `EditorStore.ensureInitial(parentUid)` 统一维护根/compound initial；
- `addState` 末尾按父级调用；
- `removeState` 对受影响父级 + 根调用；
- `setParent` 对旧父级/新父级/根调用；
- history 不作为 compound initial；
- `verify-editor` 增加 KIT-016 回归用例。
