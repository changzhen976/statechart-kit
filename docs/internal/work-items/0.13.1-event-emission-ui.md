# 0.13.1 — 内部发出事件 UI 补全

> 状态：已实现（0.13.1）
>
> 类型：编辑器展示层补丁；不改 `ProjectDoc`、SCXML 或运行时语义。
>
> 预估：0.5–1 人日。

## 问题

0.13.0 的事件面板有：

- 外部发送：普通 `send` 动作；
- 自动延时：kit 注入的延时 send；
- 接收事件：转移监听。

但 `raise` 只作为接收事件的「来源」出现，没有自己的发出视图。测试状态机里只有
`raise internal.ping` 和自动延时时，「发送事件」区域为空，容易让作者误以为事件没有发出。

## 目标

把发出事件拆成清晰的区块：

1. **外部发送**：`send` 动作，保留宿主 eventFields；
2. **内部发出**：`raise` 动作，只读，不显示 broadcast/MQTT 字段；
3. **自动延时**：保持现有内部延时区块；
4. **接收事件**：转移监听 + 来源 + 可见性。

内部发出行建议显示：

```text
事件             来源                         监听
internal.ping    left.entry（状态进入动作）    1 条转移
```

## 实现建议

- 在 `EventAttrsPanel.vue` 增加 `raiseRows`，扫描：
  - 状态 entry/exit 动作；
  - 转移动作。
- 来源标记状态/转移槽位；
- 统计监听该事件的转移数；
- 新 section 放在「外部发送」和「自动延时」之间；
- 空状态不显示整段；
- 中英文 labels 补齐。

## 非目标

- 不把 `raise` 混入 `sendRows`；
- 不给内部事件显示宿主 `eventFields`；
- 不改 `eventVisibility` 或 SCXML 守卫；
- 不做内部事件编辑器/事件重命名。

## 验收

- 含 `raise` 的文档事件面板出现「内部发出」；
- 来源显示状态/转移槽位；
- 监听数正确；
- 不出现 broadcast/MQTT 字段；
- `check:vue` 覆盖 raise 行；
- 中英文界面正常。

## 发布

作为 `0.13.1` 补丁发布；不改变 0.13.0 的事件语义。


## 0.13.1 实现记录

- `EventAttrsPanel` 增加 `raiseRows`，扫描内部 raise 的来源状态/槽位和监听数；
- 事件改名/删除时 `pruneEventVisibility` 清理孤儿可见性键；
- `canvas-select` 识别被截断的 `_event.type` 生成守卫，保证仿真画布可选中转移；
- `check-vue`、`verify-editor` 回归通过。
